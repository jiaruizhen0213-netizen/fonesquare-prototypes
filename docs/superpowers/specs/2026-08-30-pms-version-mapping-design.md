# PMS 版本映射转化规则原型设计

## 目标

将运营端现有的“MAX SKU/版本＋海外属性值 → 最终国内定价 SKU”配置，替换为由 PMS 提供基础数据的版本 PPN/PPV 映射配置。海外运营人员只选择 PMS 返回的具体值，不创建 PPN/PPV，也不直接配置目标 `skuId`。

本次只修改 `platform.html`。`store.html` 仅保留核查结论，不修改代码。

## 运营端信息架构

- 保留一级分组“商品映射管理”。
- 将二级菜单“属性值映射规则”更名为“PMS 版本映射规则”。
- 删除“候选固化治理”菜单及对应页面、弹窗、模拟数据、交互函数和事件绑定。
- 商品映射管理不再接收或固化店员选择的国内 SKU。

## 规则列表

页面标题为“PMS 版本映射转化规则”。顶部说明明确：

- PPN、源 PPV、目标 PPV均来自 PMS。
- 海外系统只能选择 PMS 返回的值。
- 页面不允许手工创建 PPN/PPV，也不直接维护目标 `skuId`。
- 规则变更只影响后续标单，历史轮次继续使用冻结快照。

统计项保留：规则总数、生效规则、停用规则、覆盖商品。

筛选条件调整为：

- 站点
- 商品或型号
- 源版本 PPV
- 目标版本 PPV
- 状态

列表字段调整为：

- 映射编号/规则版本
- 站点与商品/型号范围
- 版本 PPN
- 源版本 PPV
- 目标版本 PPV
- 海外价格策略（系数、MYR 固定调整值）
- PMS 校验状态
- 规则状态
- 更新人/时间
- 操作

## 新增与编辑规则

表单字段为：

- 站点
- 商品/型号
- 版本 PPN
- 源版本 PPV
- 目标版本 PPV
- 海外价格系数
- MYR 固定调整值
- 状态
- 变更原因

原型使用固定的 PMS 示例数据模拟级联选择：先选择商品/型号，再从该商品对应的版本 PPN和候选 PPV中选择源值、目标值。PPN/PPV均展示名称和 PMS ID。

表单中不出现 MAX SKU、MAX SKU版本、最终国内定价 SKU、目标 SKU版本或目标 `skuId`。

保存生效规则前模拟以下校验：

- PPN、源 PPV、目标 PPV必须来自当前商品的 PMS 候选数据。
- 目标 PPV必须属于所选版本 PPN。
- 目标 PPV与商品其他属性能够组成合法 SKU。
- 同一“站点＋商品/型号＋版本 PPN＋源版本 PPV”在同一时点只能存在一条生效规则。
- 价格系数必须大于 0；MYR 固定调整值必须为有效数字。
- 变更原因必填。

校验通过后保存为新规则版本；失败时在表单内提示具体原因，不使用默认 PPV、其他 SKU或历史规则回退。

## 示例数据

主示例规则：

- 站点：马来西亚
- 商品/型号：iPhone 15 / 256GB
- 版本 PPN：销售地区/版本（`PPN-REGION-001`）
- 源版本 PPV：马来版本（`PPV-MY-001`）
- 目标版本 PPV：国行版本（`PPV-CN-001`）
- 海外价格系数：1
- MYR 固定调整值：0
- PMS 校验状态：校验通过

列表可以保留香港、新加坡等示例，用来展示按站点和源 PPV筛选，但所有示例都必须遵守相同的 PMS PPN/PPV模型。

## 店员端核查结论

“购买渠道”可作为版本 PPN 的业务显示名称，其选项可作为 PPV，因此现有质检项交互结构不需要重做。但当前演示值和说明不完全符合最新需求：

- 若要演示本次场景，PPV候选应包含“海外其他版本”“马来版本”“国行版本”等 PMS 返回值。
- “MAX 不返回型号”应理解并表述为“MAX 未匹配到有效型号时，允许店员从 PMS 商品目录补选型号”。

以上只记录为后续调整项，本次不修改 `store.html`。

- 旧候选固化菜单和功能不再出现。

- 新增/编辑表单不出现目标 SKU配置。
- 唯一性、PMS候选合法性、价格字段和变更原因校验可演示。
