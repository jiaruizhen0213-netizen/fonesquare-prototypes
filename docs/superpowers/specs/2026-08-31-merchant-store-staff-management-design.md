# 商家、店铺、店员管理原型设计

## 1. 目标

将平台后台现有的“FoneSquare 回收商列表＋门店用户混合列表＋店铺列表”调整为三个独立对象页面：商家列表、店铺列表、店员列表。原型面向平台运营和管理员，用于验证统一账号下两类 App 商家数据的展示边界、门店归属，以及店员个人建拍权限的配置和实际生效状态。

本次在现有高保真交互原型中完成页面、数据和交互调整，不新建独立站点或替换现有视觉体系。

## 2. 范围

本次只修改 `platform.html` 中商家管理相关页面及对应契约测试：

- 商家列表及商家新增、详情。
- 店铺列表及店铺详情。
- 店员列表及店员详情、商家关系和个人建拍权限。
- 相关导航、演示数据、中英文文案和交互绑定。

以下内容不在本次范围：

- 默认分账、Max、竞拍、订单和财务模块的既有业务流程。
- `recycler.html`、`store.html` 的页面调整。
- 真实接口、账号认证服务或后端持久化。

## 3. 信息架构

侧边栏“商家管理”下直接展示三个独立入口，不使用 Tab：

1. 商家列表
2. 店铺列表
3. 店员列表

删除现有“门店用户”混合页面及其导航。商家主账号作为门店端商家记录的一部分展示，不进入店员列表。

## 4. 商家列表

### 4.1 数据范围与行粒度

列表同时展示：

- FoneSquare 商家记录。
- 门店端选择“我是商家”后创建的商家记录。

一行代表一个 App 内的商家记录。同一统一账号在两个 App 均有商家记录时展示两行，通过“来源 App”区分。店员档案不进入商家列表。

不是所有商家都有店铺：

- FoneSquare 商家的店铺数、店员数显示“—”，不可点击。
- 门店端商家展示实际店铺数和已关联店员数，数字可点击并跳转到对应列表，同时带入商家筛选条件。

### 4.2 列表字段与筛选

筛选项：

- 商家 ID / 商家名称 / 手机号 / 邮箱。
- 来源 App：全部、FoneSquare、门店端。
- 账号状态。
- 业务状态。

列表字段：

- 商家 ID / 商家名称。
- 统一账号 ID / 脱敏手机号或邮箱。
- 来源 App。
- 账号状态。
- 业务状态与权限。
- 店铺数 / 店员数。
- 当前 App 业务开通时间。
- 操作。

业务字段按来源 App 条件展示：

- FoneSquare：KYC、注册国家/地区、可访问站点、出价权限。
- 门店端：商家状态、商家建拍权限、分账规则状态。
- 不属于当前来源 App 的字段显示“—”，不拼接另一端数据。

### 4.3 新增和详情

商家列表保留“新增商家”入口，但仅新增 FoneSquare 商家。表单包含手机号/邮箱、FoneSquare 注册国家/地区、商家资料和 KYC 信息。

保存规则：

1. 手机号/邮箱标准化后优先复用统一账号。
2. 统一账号不存在时，在原型中模拟创建或激活账号。
3. 统一账号已有有效 FoneSquare 商家记录时阻止重复新增。
4. 统一账号在门店端的商家或店员角色不阻止新增 FoneSquare 商家。
5. 平台后台不新增门店端商家。

详情页按来源 App 展示对应资料，不允许在当前记录中直接编辑另一 App 的业务数据。

门店端商家开启商家建拍权限前，必须已有至少一个有效店铺且商家分账规则有效；条件不满足时保持关闭并提示缺失条件。开启商家建拍权限不得自动创建店铺、修改店铺数据或批量开启店员个人建拍权限。

## 5. 店铺列表

一行对应一条门店记录，页面展示名称统一为“店铺”，底层继续复用现有门店对象。

筛选项：

- 店铺编号 / 店铺名称。
- 所属商家。
- 店铺状态。

列表字段：

- 店铺编号 / 名称 / 类型。
- 所属门店端商家。
- 状态。
- 国家/地区、城市、地址摘要。
- 联系电话。
- 银行卡尾号或脱敏摘要。
- 已绑定 Max 设备数 / 启用设备数。
- 更新时间。
- 操作。

详情保留基本资料、银行卡脱敏信息、Max 设备和操作记录。删除列表、详情、表单、数据、校验和文案中的“店铺建拍权限”；店铺不是账号或权限主体。

## 6. 店员列表

一行对应一个门店端店员档案。商家主账号不进入店员列表，店员不与具体店铺绑定。

筛选项：

- 成员 ID / 姓名 / 手机号 / 邮箱 / 统一账号 ID。
- 所属商家。
- 关联状态：待关联、已关联、已解除。
- 账号状态。
- 个人建拍权限配置。
- 实际权限状态。

列表字段：

- 成员 ID / 姓名。
- 统一账号 ID / 脱敏手机号或邮箱。
- 当前所属商家。
- 关联状态。
- 账号状态。
- 个人建拍权限配置。
- 实际权限状态。
- 关联时间 / 解除时间。
- 操作。

所属商家展示规则：

- 已关联：展示当前有效商家。
- 待关联或已解除：显示“—”。
- 历史所属商家只在详情和操作记录中展示。

详情支持关联商家、解除关系、转移商家和调整个人建拍权限，并保留历史关系和操作记录。

## 7. 店员建拍权限

每个店员可独立开启或关闭个人建拍权限。个人配置不会修改商家建拍权限，实际权限按以下规则计算：

| 商家建拍权限 | 店员个人配置 | 实际状态 |
|---|---|---|
| 开启 | 开启 | 已生效 |
| 开启 | 关闭 | 已关闭 |
| 关闭 | 开启 | 未生效（商家权限关闭） |
| 关闭 | 关闭 | 已关闭 |

商家权限关闭时保留店员个人配置。商家权限再次开启后，个人配置为开启的店员自动恢复“已生效”。

列表直接展示“个人配置”和“实际状态”，避免只显示一个开关而误导运营人员。切换个人配置后，当前行和详情页的实际状态立即刷新。

## 8. 异常与反馈

原型至少覆盖以下异常状态：

- 手机号和邮箱分别匹配不同统一账号：阻止新增并提示联系平台处理。
- 统一账号已有有效 FoneSquare 商家记录：阻止重复新增。
- 店员关联或转移时存在有效角色、商家关系冲突：拒绝操作，不覆盖原关系。
- 店员个人权限已开启但商家权限关闭：显示“未生效（商家权限关闭）”，不显示为可建拍。
- 搜索无结果：展示与当前筛选条件对应的空状态。

所有保存、启停、关联、解除和转移操作均提供明确的成功或失败反馈。

## 9. 实现边界

- 继续沿用 `platform.html` 现有单文件数据、渲染、事件委托和中英文翻译结构。
- 商家、店铺、店员使用独立渲染函数和筛选状态，避免继续复用“门店用户”混合模型。
- 允许门店端商家主账号数据继续作为商家记录存在，但不得复制到店员数据中。
- 只调整本次范围内的导航、DOM、演示数据、渲染、校验、导出和事件绑定，不做无关重构。

## 10. 验收标准

1. 侧边栏存在商家列表、店铺列表、店员列表三个独立入口，无“门店用户”入口。
2. 商家列表同时展示 FoneSquare 和门店端商家，并正确显示来源 App。
3. FoneSquare 商家的店铺数和店员数显示“—”；门店端商家的数量可跳转并带入筛选。
4. 后台新增商家只创建 FoneSquare 商家，账号冲突和重复商家均被阻止。
5. 店铺列表和详情不再出现“店铺建拍权限”。
6. 店员列表不包含商家主账号，并正确展示当前商家、关联状态和历史关系入口。
7. 每个店员可独立配置个人建拍权限，实际状态严格按商家权限与个人配置共同计算。
8. 商家权限关闭时，个人配置保留且显示未生效；重新开启后自动恢复实际状态。
9. 商家建拍权限仅在存在有效店铺且分账规则有效时可开启，开启时不自动创建店铺或修改店员个人配置。
10. 三个列表的搜索、筛选、空状态、详情和主要操作可交互演示。
11. 默认分账、Max、竞拍、订单和财务模块的既有流程不受影响。
12. 中英文切换后，新增和变更的页面、字段、状态及提示均有对应翻译。
13. 契约测试覆盖导航结构、条件字段、权限状态矩阵、旧概念清理和范围外模块保护。
