# FoneSquare 平台端退款与财务原型对齐设计

## 1. 目标与依据

本次只修改 `platform.html`，使平台端成交订单中的退款能力、资金台账、预付金和月度结算原型与以下当前远端文档一致：

- 《【平台端】成交订单、隐私退回与资金管理 MVP 产品需求文档（待评审）》revision 285。
- 《【平台端】资金台账与线下处理 MVP 产品需求文档（开发评审稿）》revision 469。

用户已明确成交订单模块基本完成人工确认，因此取货、隐私、轻量退回、订单列表主体布局和现有批量操作保持不变。成交订单只修改会造成退款规则错误或验收失败的字段、状态、按钮和演示交互；财务管理按需求重构。

本次继续使用单文件静态 HTML、内嵌 CSS 和 JavaScript，不增加构建工具、后端或运行时依赖，并保留现有桌面后台视觉语言与中英文切换。

## 2. 业务边界

### 2.1 退款与售后

- 售后与退款是两个独立业务对象。
- 售后不生成资金方向，不修改预付金或财务结算。
- 每个订单最多存在一张有效退款；退款记录状态为草稿、已发起或已取消。
- 保存退款草稿不影响资金。
- 业务正式发起退款后立即生效，冻结原因、说明、退款总金额和一条或多条资金方向。
- 财务不发起、确认、驳回或取消退款，也不在资金台账中编辑退款金额或资金方向。
- 退款不以取货、隐私、退回或售后状态为前置条件。
- 结算锁定前，业务可以取消已发起退款；取消原因必填，并追加反向资金影响，不覆盖原记录。

### 2.2 退款权限与结算状态

- 退款权限为可发起、已锁定、已关闭。
- 结算单处于草稿时，来源订单可以发起或取消退款；草稿按最新有效退款资金方向重新计算。
- 结算单提交为待处理后锁定来源订单退款。
- 待处理结算单退回草稿时重新开放来源订单退款。
- 结算单已处理后永久关闭来源订单退款入口。
- 结算单冲正只纠正财务处理事实，不重新开放业务退款，也不产生“结算后退款进入下一期”的业务路径。

### 2.3 退款资金影响

- 对门店的退款只恢复对应站点、业务归属门店和币种的预付金，不形成现金应付。
- 其他退款资金方向进入待结算，并与正常资金方向共同计算结算净额。
- 全额或部分退款由有效退款金额和订单可退上限自动判断，不作为财务审批结果。

## 3. 成交订单最小修改设计

### 3.1 列表与统计

- 保留现有筛选布局、表格结构、取货、隐私和退回批量操作。
- 将“待处理退款”统计改为“已发起退款”。
- 退款展示改为业务状态与金额类型组合，例如“已发起 · 部分退款”或“已取消”。
- 在退款/结算相关列展示退款记录号、有效退款金额、退款权限和财务结算状态。
- 订单处理列根据权限展示：
  - 可发起且没有有效退款：发起退款。
  - 可发起且存在已发起退款：查看退款、取消退款。
  - 已锁定或已关闭：只展示查看退款，并显示锁定或关闭原因。
- 删除“申请退款”“等待财务处理”和退款申请处理状态。

### 3.2 订单详情

- 保留基本信息、隐私与退回、资金明细和操作日志页签。
- 将“退款与售后”页签内部拆为退款记录区和售后记录区，两者使用独立按钮、状态与列表。
- 退款区展示退款记录号、原因、说明、总金额、金额类型、多条资金方向、发起或取消信息、预付金影响、退款权限和财务结算状态。
- 售后区只展示售后事实，不展示资金状态、金额生效或财务冲正入口。
- 删除“退回中禁止退款”“等待退回完成”“财务确认已处理后生效”等文案和交互。
- 增加取消退款弹窗：取消原因必填，成功后保留原记录并追加反向资金方向。

### 3.3 退款创建

- “申请退款”统一改为“发起退款”。
- 创建页允许保存草稿和正式发起。
- 正式发起前校验订单退款权限、是否已有有效退款、金额上限和至少一条有效资金方向。
- 正式发起成功后立即更新订单退款状态、有效退款金额、预付金恢复和待结算资金明细，不创建待财务确认的申请。

## 4. 财务管理信息架构

财务管理保留一级导航，在其下提供三个页面：

1. 分账明细：逐笔查询资金事实、预付金和门店付款，支持人工补充批次。
2. 结算单：查看月度操作批次与拆分后的结算单，完成提交、退回草稿、线下处理和冲正。
3. 结算配置：维护站点自然月自动建单配置及查看调度结果。

原“资金台账”页面改为“分账明细”，原“结算账单”统一改为“结算单”。删除退款申请与资金记录混排、退款处理队列和退款确认/驳回弹窗。

## 5. 分账明细设计

### 5.1 汇总与筛选

- 汇总卡按当前筛选结果展示待结算金额、已结算金额和已生效退款金额。
- 预付金关注卡按站点、业务归属门店和币种分别展示可用余额、本月使用额、本月退款恢复额和本月门店垫付额。
- 本月门店垫付额大于零时展示“前置款不足，建议关注”。
- 筛选包括业务时间、站点、付款/收款主体及账户、门店端商家、业务归属门店、店员、回收商、业务类型、处理类型、币种、退款状态、退款权限、资金明细结算状态、结算单状态、订单号、操作批次号、结算单号和 SKU。

### 5.2 列表与详情

- 列表逐笔展示资金明细号、业务类型、业务时间、订单与 SKU、业务归属门店、付款和收款主体及账户、处理类型、币种、原始金额、待结算金额、退款信息、预付金影响、操作批次和结算单关系。
- 资金明细状态使用待结算、已纳入结算单、已结算、已抵扣和已冲正。
- 退款状态、金额、退款记录号、资金方向和退款权限全部只读。
- 详情展示业务快照、账户快照、预付金与门店付款、结算关系、凭证、调整、结转和审计记录。

### 5.3 财务操作

- 提供“登记预付金”，支持发放、追加充值和退回；已生效记录只能冲正。
- 提供“登记门店付款”，系统将付款金额拆分为预付金使用额和门店垫付额；余额不足不阻断登记。
- 追加充值只影响登记后的可用余额，不追溯修改历史付款拆分或垫付额。
- 提供“创建人工补充批次”，只允许勾选符合条件的明细；正常月度结算不依赖人工创建。

## 6. 月度结算设计

### 6.1 自动建单与拆单

- 自动建单以站点为调度单位，周期固定为站点时区的自然月，区间左闭右开。
- 月末到达配置时间后，系统创建月度操作批次草稿；无符合条件明细时不创建空批次，只展示执行结果和原因。
- 结算单按处理类型、付款主体及账户、收款主体及账户、方向和币种拆分，不再按商家 ID 生成一张混合账单。
- 草稿纳入未进入其他有效结算单且金额有效的正常资金明细、已生效退款资金明细和有效财务调整。
- 退款使用正式发起时冻结的实际资金方向；不得按退款总额重新按成交分账比例推算。

### 6.2 状态与操作

- 结算单状态为草稿、待处理、已处理和已冲正。
- 草稿支持重新计算和提交。
- 提交时重新校验退款版本、是否重复纳入、金额版本、收付款主体及账户和币种；失败时保持草稿并展示具体订单或主体原因。
- 提交成功后进入待处理，冻结来源、资金明细、金额、预付金抵扣与恢复、门店垫付补回和账户快照，同时锁定来源订单退款。
- 待处理支持退回草稿和标记已处理；单张结算单不支持部分处理。
- 标记已处理时记录处理方式、处理时间、账户、凭证和说明。线下转账或现金必须有凭证；无需实付或负数结转必须有说明。
- 已处理结算单支持财务冲正；冲正原因必填，生成关联的反向结算单并保留全部历史。

### 6.3 金额与结转

- 结算净额按同一结算主体和币种汇总正常资金方向和已生效退款现金方向，再计算手续费抵扣、财务调整和预付金抵扣。
- 对门店的退款只恢复预付金，不进入现金净额。
- 净额大于零时形成实际收付款；等于零时无需实付；小于零时本单处理至零，剩余负数生成后续结转项。
- 结转项只能进入处理类型、收付款主体及账户、方向和币种完全一致的后续结算单。

## 7. 结算配置设计

- 配置字段包括站点、是否启用自动建单、固定自然月周期、生成时间、生效日期和状态。
- 同一站点同一时刻只允许一条生效配置。
- 新配置只作用于尚未开始的月份，不回溯重算已生成草稿。
- 页面只读展示站点时区、当前结算月、下次生成时间、最近执行结果、操作批次号或未建单原因。
- 原型提供启用、停用和保存新版本的演示交互，但不展示定时任务、接口、幂等键或数据库字段。

## 8. 双语、异常与审计

- 所有新增或修改的可见文案同时提供简体中文和英文翻译。
- 重复提交、重复处理、重复登记在原型中返回首次结果提示，不生成重复记录。
- 账户缺失、退款版本变化、金额冲突和明细重复纳入分别展示明确的失败原因。
- 退款发起/取消、预付金、门店付款、月度建单、提交锁定、退回草稿、线下处理、结转、冲正和导出均在演示数据中保留操作人、时间、对象、原因和前后状态。

## 9. 测试与验收

新增独立 Node 契约测试，至少验证：

- 原型不存在“财务确认或驳回退款”“等待财务处理”“退回中禁止退款”和“结算后退款进入下一期”等旧口径。
- 订单退款具备草稿、正式发起、取消、可发起、已锁定和已关闭状态及对应交互函数。
- 财务端不存在退款处理按钮，退款资金方向只读。
- 财务导航包含分账明细、结算单和结算配置。
- 预付金登记、门店付款、门店垫付和前置款提示存在。
- 结算单具备草稿、待处理、已处理、已冲正以及提交、退回草稿、处理和冲正入口。
- 结算单拆分和详情包含收付款主体及账户、方向、币种、退款现金方向、预付金抵扣与恢复、门店垫付补回和结转。
- 平台内联 JavaScript 可编译，全部现有测试继续通过。

页面验收覆盖：订单无需退回即可发起退款、退款立即生效、结算待处理后退款锁定、退回草稿后重新开放、已处理后永久关闭、门店退款恢复预付金、余额不足时形成门店垫付、月度草稿提交与冲正、中文和英文切换。
