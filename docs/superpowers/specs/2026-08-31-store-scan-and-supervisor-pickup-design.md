# 门店员工扫码建标与督导提货原型设计

## 1. 目标与范围

仅修改 `store.html`，保持平台运营端和回收商端不变。原型继续支持简体中文与英文，并只展示用户可操作、可观察的页面和结果，不展示后台实现细节。

本次包含两个彼此隔离的移动端工作区：

1. 门店端/员工 App：员工直接扫码开始建标，扫码后自动带入 IMEI 和识别出的设备信息。
2. 督导 App：督导使用独立 OB 身份进入现场提货工作台，不能与门店员工身份合并。

督导提货规则以飞书文档《【督导 App】现场取货 MVP 产品需求文档（待评审）》修订版 21 为依据。

## 2. 方案比较与结论

### 方案 A：同一 HTML 原型承载两个独立工作区（采用）

在现有移动端框架内增加“督导 App”演示入口，但账号、首页、导航和数据范围与门店员工完全分离。优点是沿用现有发布地址，便于一次演示完整业务；同时保留 PRD 要求的身份隔离。

### 方案 B：给门店员工直接增加提货权限（不采用）

交互路径最短，但违反督导使用 OB 账号、不得与门店账号合并的规则，也会混淆门店业务数据范围。

### 方案 C：新增独立 `supervisor.html`（暂不采用）

与真实产品形态最接近，但会增加新的发布地址和演示入口。本次用户明确要求修改门店端/员工 App 原型，因此优先在同一原型文件中隔离演示。

## 3. 员工扫码建标流程

### 3.1 入口与主流程

员工点击首页“扫码质检并建标”后直接进入扫码页，不再进入“选择回收物品”、品类、品牌或型号选择页面。

扫码成功后进入质检页并展示：

- 自动识别的设备型号；
- 自动带入且只读展示的 15 位 IMEI；
- 质检工具结果和需要员工手动补充的动态质检项；
- 当前是否命中折叠屏照片规则。

原型提供“普通手机”和“折叠屏手机”两种扫码演示结果，以便验证条件分支。扫描失败时停留扫码页，并提供重新扫码入口。

### 3.2 照片规则

- 普通手机：不展示也不要求“关于本机”照片或其他本机照片。
- 折叠屏手机：动态展示“亮屏照片”和“暗屏照片”两个必传项。
- 折叠屏任一照片缺失时，不能提交质检结果；页面明确提示缺失项。
- 照片要求由设备识别结果触发，员工不手动选择设备是否为折叠屏。

### 3.3 后续流程

质检报告确认、价格失败不阻断发布、发布前不收集卖家手机号和合同、卖家决定以及重拍自动沿用等既有规则保持不变。

## 4. 督导 App 现场提货流程

### 4.1 身份与入口

原型增加独立“督导 App”演示入口。督导使用 OB 账号身份，不属于商家主账号或门店员工，不建立商家成员关系。

演示登录成功后进入督导工作台；页面展示当前督导、负责范围和版本信息。原型同时提供无督导角色、未分配范围和账号不可用的结果提示，但不展示后台权限配置过程。

### 4.2 现场提货工作台

默认展示当前督导负责范围内的待取货成交订单，包含：

- 顶部统计：待取货数、超过 72 小时数、今日已取货数；
- 筛选：区域、门店、回收商、订单号/标单号/商品或 SKU、取货状态；
- 列表：订单与商品、门店、回收商、实际建拍操作人、成交时间和取货状态；
- 状态切换：待取货与已取货。

不展示成交金额、分账、佣金、退款、资金、隐私或退回处理信息。

### 4.3 单笔确认

督导进入订单详情核对订单、商品、门店、回收商和实际建拍操作人后，点击“确认已取货”。二次确认说明状态不可撤销；确认成功后订单变为已取货，并展示实际取货时间和督导。

### 4.4 批量确认

待取货列表支持多选：

- 首个选中订单确定本次操作的门店和回收商；
- 仅同一门店、同一回收商、仍为待取货的订单可继续选择；
- 二次确认页展示订单清单；
- 任一订单校验失败时整批不提交；
- 成功后逐单更新为已取货。

页面不创建或展示取货批次、批次号、交接码，也不提供扫码取货。

### 4.5 异常与重复操作

- 账号、角色或范围失效：阻止提交并展示明确原因。
- 订单已被其他人处理或版本变化：保留当前页面，提示刷新状态。
- 批量条件不一致：不允许选择并解释必须同门店、同回收商。
- 网络超时：允许重试；重复提交只展示首次成功结果，不重复更新。
- 已取货：不可撤销或回退为待取货。

## 5. 信息架构与视觉原则

门店员工工作区沿用现有浅色移动端视觉和底部导航。督导工作区使用相同基础组件，但通过“督导 App / OB 账号”标题、独立首页和独立底部导航明确身份边界，避免用户误以为普通员工拥有督导权限。

语言切换继续放在“我的/设置”中。新增页面、弹窗、校验提示、状态和动态文案必须中英文一一对应。

## 6. 验收标准

1. 员工从首页建标入口直接进入扫码页，源码和可见流程中不再出现先选品类、品牌或型号的建标步骤。
2. 扫码后 IMEI 自动带入，不提供手工录入和“关于本机”照片上传。
3. 普通手机无需照片即可继续；折叠屏必须完成亮屏、暗屏两张照片。
4. 督导 App 使用独立 OB 身份，普通门店员工不能执行提货。
5. 督导可查看负责范围内待取货订单，并完成单笔或同门店、同回收商的批量确认。
6. 提货成功后逐单更新为已取货且不可撤销，不出现批次、批次号、交接码或扫码提货。
7. 督导端不展示金额、财务、隐私、退款和退回操作。
8. 新增流程在简体中文和英文下均可完整演示，页面无运行时错误。
9. 既有价格、发布、卖家决定和重拍规则不被破坏。

## 7. 验证方式

- 新增静态回归测试，检查旧选型流程和“关于本机”照片残留已删除。
- 新增扫码、普通手机、折叠屏双照片、督导单笔提货、批量约束和不可撤销状态的交互测试。
- 运行全部 Node 测试和脚本编译检查。
- 使用 Codex 内置浏览器分别验证中文与英文完整路径。
- 推送后验证 GitHub Pages 返回新版本并检查线上渲染与控制台错误。
