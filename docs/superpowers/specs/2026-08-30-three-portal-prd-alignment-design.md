# FoneSquare 三端原型与当前 PRD 对齐设计

## 1. 目标

以“产品文档”知识库当前全部 PRD 为唯一业务口径，更新以下三个 GitHub Pages 原型：

- `platform.html`：平台运营端。
- `store.html`：供货商门店端与员工演示端。
- `recycler.html`：FoneSquare 回收商端。

本次保留现有视觉语言、导航框架和单文件静态原型结构，集中修正用户可见的角色、字段、状态、操作和演示流程。三端均支持简体中文和英文切换。

原型只展示用户需要看到、操作或理解的业务结果，不展示幂等键、技术重试任务、后台配置过程、接口调用过程等系统实现细节。

## 2. 统一业务口径

### 2.1 账号和端口

- 商家管理 PRD 是账号、商家、角色、数据范围和建拍权限的唯一准文档。
- FoneSquare 只承载回收商端能力。
- 门店端和员工 App 属于供货端。
- 供货端登录角色只有商家主账号和店员，不存在店铺主账号。
- 店铺只是供货商家下的业务归属和筛选维度，不是账号、角色或独立结算主体。
- 商家主账号可查看本商家下属店铺的业务；店员只查看本人作为实际建拍操作人的业务。

### 2.2 质检和价格

- 供货端保存并展示真实质检事实、PMS 基础产品/SKU、最终等级、版本 PPN、来源 PPV、模板和规则版本。
- 供货端不得提供国内定价 SKU 搜索、手工选择或修改入口。
- 价格链继续使用 PMS 的 PPN/PPV 转换：来源 PPV 转换为目标 PPV，校验合法组合，生成价格编码和等级，查询 P1 并冻结本轮 MYR 基准价。
- 价格模块只提供本轮冻结价或明确的价格失败结果，不拥有出价计划。
- 价格失败不阻断标单发布和普通报价；无有效基准价时不做普通报价偏差提示，也不生成依赖冻结价的阶梯出价计划。

### 2.3 发布、卖家决定和重拍

- 发布前不采集卖家手机号、邮箱、WhatsApp、合同勾选、合同编号或附件。
- 竞拍结束产生预中标后，仅本轮实际创建人可以记录卖家决定。
- 卖家接受时，本轮实际创建人维护合同、马来西亚 `+60` 手机号并完成 OTP；校验通过后生成唯一成交订单。
- 卖家拒绝时，本轮实际创建人选择“重拍”或“结束标单”，系统不自动替用户决定。
- 选择重拍后，只有质检报告完成不超过 1 小时且设备仍在店，才在同一标单下创建新轮次；否则结束并提示重新质检、发布。
- 同标单新轮次自动沿用每个回收商最近一轮最高有效主动报价。有效期自原轮次结束起固定 48 小时，不重置、不延长；沿用价不触发 30 秒窗口；新轮次首次主动报价必须高于沿用价，成功后触发新的固定 30 秒窗口。

### 2.4 爱回收阶梯出价

- 爱回收是使用 FoneSquare 的回收商。
- 竞拍模块按后台启用的 FoneSquare 回收商商家 ID 配置识别爱回收资格，不使用供货商家 ID 或标单归属判断。
- 阶梯出价计划唯一归属竞拍专项：最后 20% 内随机执行 3 档 `90% / 95% / 100%` 或 4 档 `80% / 90% / 95% / 100%`。
- 普通回收商端不展示冻结基准价、偏差比例、内部策略参数或爱回收计划。

## 3. 平台运营端设计

### 3.1 商家、账号和店铺

- 将商家管理页面明确拆分为回收商商家和供货商家两个业务域。
- FoneSquare 注册商家归入回收商域；门店端商家主账号和店员归入供货商家域。
- 删除“店铺主账号”字段、列表列、详情卡片、编辑弹窗、创建店铺必选责任账号和相关状态变更代码。
- 店铺详情只展示所属供货商家、业务状态、建拍权限、地址、设备和历史记录。
- 店员关系展示为“所属商家”，不展示负责门店或店铺账号身份。

### 3.2 PMS 映射和价格

- 保留当前 PMS 通用属性映射管理：商品、属性项 PPN、源 PPV、目标 PPV和合法组合校验。
- 价格相关页面只展示每轮价格结果、价格版本、成功或失败状态和冻结 MYR 基准价。
- 删除价格模块创建自动报价任务、识别爱回收、维护阶梯计划或重试计划的文案和操作。
- 价格失败状态明确显示“不阻断发布和普通报价”。

### 3.3 标单与竞拍

- 发布快照展示 PMS 基础产品/SKU、最终等级、版本 PPN、来源 PPV、销售报告和原始质检事实；不再以“最终国内定价 SKU”作为供货端确认结果。
- 卖家决定页展示实际创建人、接受/拒绝结果，以及拒绝后的“重拍/结束标单”选择。
- 重拍弹窗只呈现业务条件和结果：报告不超过 1 小时、设备仍在店、新轮次重新取价、历史最高有效主动报价自动沿用。
- 竞拍轮次的阶梯出价页展示爱回收 FoneSquare 回收商商家、资格状态、3/4 档计划及执行结果；资格来源显示为回收商商家 ID 配置。
- 普通报价日志展示主动报价、沿用报价、固定 48 小时截止时间和 30 秒窗口状态。

### 3.4 订单、取货和售后

- 订单主状态只保留“待取货”和“已取货”，删除“关闭订单”按钮与“已关闭”状态。
- 督导现场取货只逐单更新实际取走订单，不创建取货批次、批次号、交接码或门店确认动作。
- 隐私不通过只记录检测事实，不自动创建退回；退回仍由平台人员主动发起。
- 保留当前资金台账、退款、冲正和线下处理展示，但不得表现为在线付款或退款。

## 4. 供货商门店端设计

### 4.1 角色和数据范围

- 演示角色切换只保留“商家主账号”和“店员”。
- 删除“店铺主账号”选项、翻译、权限分支和页面文案。
- 商家主账号展示本商家业务和店铺筛选；店员只展示本人标单、订单和佣金。
- 页面标题和说明使用“供货端”或“门店端/员工 App”，不得将 FoneSquare 写成供货端。

### 4.2 质检与发布

- 商品与质检页面展示 PMS 基础产品/SKU、最终等级、版本 PPN、来源 PPV 和真实事实来源。
- 删除国内定价 SKU 确认、搜索和人工选择口径。
- 发布确认页删除卖家手机号、邮箱、WhatsApp、合同勾选、合同编号和相关必填校验。
- 发布页展示价格结果卡片：成功时显示“本轮价格已生成”；失败时显示“价格暂不可用，不影响发布与普通竞价”。供货端不展示目标 PPV、P1、汇率或计算过程。
- 发布动作仍校验账号、建拍权限、店铺归属、质检快照、报告时效、设备仍在店、设备唯一性和风险。

### 4.3 预中标与重拍

- 预中标页面保留接受和拒绝入口。
- 点击接受后再展示合同确认、`+60` 卖家手机号、发送 OTP 和验证码输入；校验成功后生成唯一成交订单。
- 点击拒绝后展示“重拍”和“结束标单”两个选择。
- 重拍结果页面显示条件校验结果、新轮次编号和“历史最高有效主动报价自动沿用”；不展示内部接口或任务信息。
- 条件不满足时显示结束标单和重新质检、发布提示。

### 4.4 取货和账务

- 订单和取货结果只读，不出现取货批次、批次号、交接码、门店确认或供货端取货操作。
- 商家主账号可查看本商家店铺账务和员工佣金；店员只查看本人佣金。

## 5. 回收商端设计

### 5.1 身份和个人中心

- 明确页面属于 FoneSquare 回收商端。
- 删除将认证地址用于“门店设置”的入口、表单和文案；回收商不维护供货门店。
- KYC 不作为报价前置条件。账号有效、出价权限开启且轮次可报价即可报价。

### 5.2 报价和改价

- 普通报价首次成功后开启固定 30 秒改价窗口；改价不重置窗口，不提供撤回。
- 有有效 MYR 基准价且报价偏差大于 100% 时，只展示风险确认，不拦截提交。
- 无有效基准价时不展示偏差提示，仍允许普通报价。
- 页面不得展示 MYR 基准价、偏差百分比、价格策略或爱回收内部阶梯计划。

### 5.3 重拍轮次和订单

- 新轮次存在沿用报价时，展示“历史报价已沿用”、沿用金额和固定有效截止时间。
- 沿用本身不触发 30 秒窗口；新轮次首次主动报价必须严格高于沿用价，成功后才启动本轮 30 秒窗口。
- 卖家拒绝或超时时，回收商只读查看未成交原因；是否重拍由供货端实际创建人决定。
- 订单只展示待取货、已取货以及平台售后和资金调整结果；回收商不能修改平台现场取货结果。

## 6. 双语规则

- 三个页面都保留简体中文和英文切换。
- 新增或修改的所有可见文案必须同时提供中英文翻译。
- 切换语言不得改变当前页面、角色、表单状态、竞拍轮次或报价数据。
- 中文和英文页面必须呈现相同业务字段、按钮和状态，不允许只在单一语言中删除旧口径。

## 7. 实现边界

- 继续使用三个独立 HTML 文件内嵌 CSS 和 JavaScript，不引入构建工具或后端依赖。
- 保留现有视觉设计、移动端壳体、桌面运营后台布局和模拟数据风格。
- 只做支撑当前 PRD 的局部结构调整，不进行无关的框架重构。
- 不展示幂等键、技术重试、API 名称、数据库字段、分布式事务或后台定时任务。
- 本地 `main` 当前领先 `origin/main` 的 12 个既有提交已获用户授权，最终推送时与本次修改一并发布。

## 8. 验收与发布

### 8.1 自动化验收

- 为三端新增契约测试，检查必需的新文案、控件和交互函数存在。
- 检查旧口径残留不存在，包括“店铺主账号”、发布前合同/手机号必填、国内定价 SKU 选择、价格模块拥有出价计划、供货端取货批次和订单关闭。
- 编译执行三个页面的内联 JavaScript，确保无语法错误。
- 测试中英文翻译表包含本次全部新增文案。

### 8.2 页面验收

- 平台端检查商家管理、价格结果、竞拍轮次、卖家决定、重拍、订单和现场取货页面。
- 供货端分别以商家主账号和店员演示发布、预中标接受、拒绝重拍、订单与账务页面。
- 回收商端检查普通报价、有/无基准价、沿用报价、30 秒改价和个人中心。
- 三端分别切换中文和英文，确认页面无缺失、遮挡、死按钮或旧文案。

### 8.3 发布

- 在本地完成测试和页面验收后提交代码。
- 推送本地 `main` 到 `origin/main`。
- 等待 GitHub Pages 更新并重新打开 `platform.html`、`store.html` 和 `recycler.html` 验证线上版本。
